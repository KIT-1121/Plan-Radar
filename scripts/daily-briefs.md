# 日刊更新流程（Plan-Radar）

目标：让首页「AI 科技简报」每天都有新内容，**日报每个自然日至少 3 条**，
标题与摘要保持中文、准确、可读。

## 1. 抓素材

```powershell
cd D:\harness\kit_code\Plan-Radar
node scripts/fetch-news.mjs --days 3 --per-day 6
```

脚本会按北京时间分组输出标题、时间、链接和原文摘要。若某个源失败，脚本会在末尾提示；
少于 3 条时用 `web_search` 补，不要编造。

## 2. 选稿

- 日报：当天至少 3 条，可覆盖昨天，总量 6–8 条；优先模型、算力、融资、监管、
  安全和大厂路线之争，跳过纯产品促销和活动报名。
- 周刊：每周一换一轮，保留 4–6 条，覆盖上一周的行业结构性变化。
- 月刊：每月 1 日换一轮，保留 4–6 条，选能代表当月方向的节点。
- 同一条新闻只出现一次；链接必须是原文，摘要不超过 45 个汉字。

## 3. 写中文

- 标题 12–22 个汉字，陈述事实，不用「震惊」「炸裂」这类词。
- 摘要一句话讲清「发生了什么 + 为什么重要」，不堆形容词。
- 日期用 `MM.DD`（日报）、`本周`（周刊）、`10 月`（月刊）。
- 只写原文能支撑的内容；拿不准的数字和因果就不写。

## 4. 改文件

只改 `lib/briefs.ts`：

1. 在日报数组顶部插入新条目（新的在前），保留最近 3 天，确保每天 ≥3 条。
2. 把 `briefsUpdatedAt` 改成当天日期，例如 `2026.11.03`。
3. 不要动界面结构和 CSS；如确需改样式，先说明原因。

## 5. 验证

```powershell
pnpm typecheck
pnpm build
```

两者都通过后再提交。需要看效果时启动 `pnpm dev`，用浏览器截图核对首屏和简报区。

## 6. 提交

```powershell
git add lib/briefs.ts
git commit -m "chore: daily briefs 2026.11.03"
git push origin main
```

推送失败时不要强推；保留改动并报告失败原因。

## 定时执行

- 当前由 DSH 定时任务每天 08:00（Asia/Shanghai）触发本流程。
- 手动跑一次：把上面的步骤按顺序执行即可。
- 机器关机或会话未运行时任务不会执行；恢复后补跑最近一天，不用补很多天。
